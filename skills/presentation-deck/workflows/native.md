# Native PowerPoint workflow

For native PPTX, [layout history and contextual image reuse](PPTX_LAYOUT_ORIGINALITY_POLICY.md) requires actual geometry extraction, comparison with previous PPTX products across sessions, and Main visual judgment. Repeated composition rejects despite cosmetic/shape changes; same photos may recur only after current tone/content/purpose checks. Keep the evidence in Quick as well as Default/template workflows.

For native PPTX creation or substantial deck redesign with a slide roster, follow [Main review of the first three slides](PPTX_FIRST_THREE_SLIDES_REVIEW.md). Author/render slides 1–3 first; Main records PASS before slide 4 onward may be authored. This applies to Default, Quick and deck/template production. Keep the review receipt even when other planning stays in context; no routine user reapproval is required.

For sourced photographs, load [PPTX_IMAGE_SELECTION_POLICY.md](PPTX_IMAGE_SELECTION_POLICY.md) before acquisition. Main and one GPT-6.1 Sol (Codex) / Claude Opus 5.5 (Claude Code) Engineer at Extra High (`xhigh`) own the search/review/embed loop. Main takes over search after two rejected Engineer rounds for a stable slot. Run its handoff check before insertion and final check after rendering; include the slide-to-image placement map.

Load [PPTX_SIZE_POLICY.md](PPTX_SIZE_POLICY.md) before creating slides or templates. New PPTX defaults to **10 × 5.625 inches, landscape** (`ppt169onscreen`, SVG 960 × 540). Use this owned runtime's `init` to persist `pptx_canvas.json`, including quick mode. A current explicit `--format` or `--size-inches WIDTH HEIGHT` overrides the default. Existing-source edits preserve original dimensions. This is exclusively a PPTX policy; web and other products keep their own sizes.

Owner balance gates (owner rule, 2026-10-15) run on every rendered slide set before Main reviews it (pilot 1–3 and each full-deck version) and again on the final export inside the closing gates. Gate 1, `python <CAPABILITY_ROOT>/runtime/design_brain_pptx_group_align_check.py <deck.pptx> [--panel N:x0:x1 --exclude-pictures N] --json <receipt>`, is the owner's acceptance test on the file: the union of all shape frames on each slide must be centred, so grouping the content and applying Arrange > Align > Align Center + Align Middle moves nothing (tolerance 0.05 pt; `--panel` for a slide whose remaining block is centred beside a full-bleed photo). Gate 2, `python <CAPABILITY_ROOT>/runtime/design_brain_pptx_visual_balance.py <render_dir> --side 48 --tol 2 [--ignore N:x0:y0:x1:y1 --left N:x --right N:gap --tol-slide N:units] --json <receipt>`, measures native renders: gap above = gap below (±2 units), sides 48 (±2), hairlines count; `--tol-slide` records a documented per-slide allowance (for example PowerPoint chart-space padding). Both must PASS on every slide; a placement repair is one offset for the whole slide block, never a resize or respacing, and a disagreement above 2 units between the gates means a frame is not tight to its rendered content. Keep both JSON receipts with the build evidence; `--self-check` on either script proves the gate itself.

The Codex Design runtime is internal to this capability. Resolve absolute paths from `CAPABILITY_ROOT`; use `python <CAPABILITY_ROOT>/runtime/presentation.py ...` (or `--python <interpreter>`). `BRAIN_DESIGN_PYTHON` is the shared host interpreter override. Install `runtime/requirements.txt` into the selected environment when dependencies are missing; do not change global configuration unnecessarily.

Run `doctor` to verify integrity and CLI imports. It does not prove export or visual readiness. Use `route --task "..."` to inspect the intended operation. Shared design is owned by `../design/WORKFLOW.md`.

Choose individual primitives deliberately; do not use the same full-layout scaffold to create sibling marketplace products. Source-preserving edits must compare chart/table styles and text layout.
