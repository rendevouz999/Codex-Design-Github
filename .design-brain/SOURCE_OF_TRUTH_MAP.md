# Presentation source-of-truth map

1. Explicit current user instruction, within host/system safety and real permissions/capabilities.
2. OWNER_GUARD, CONTEXT_PRIORITY and runtime/PRODUCTION_EXECUTION_POLICY for scoped owner authority and execution-route choice.
3. PRESENTATION_SCOPE and AUTOLOAD_POLICY: this plugin owns presentation templates/decks and necessary support only.
4. `skills/presentation-deck/SKILL.md`, `design/WORKFLOW.md` and full PRESENTATION_TEMPLATE_GUIDE: one presentation owner.
5. Native workflow and PPTX size/image/first-three-slide/originality policies, or web intelligence/stage/motion/delivery/source-bridge policies, according to actual output.
6. Shared memory/reference cognition, no-copy and reference/name-usage evidence.
7. Cognition contract/gate, meaningful simulation, layout originality, sequential build-session lifecycle and batch provenance.
8. Actual authoring; target-specific source/editability and design-system requirements.
9. Native/web/host-target technical/render/visual review, post-build audits, repairs, completion receipt and lifecycle verify-final.
10. Controlled learning/reflection. Craft/TypeUI are support only; README/quick starts are documentation.

Main plus exactly one explicitly selected Engineer remains the plugin-scoped team. Main owns creative direction/delegation/PASS-or-REVISE. SDK is an explicitly selected alternative worker, not another participant. Existing host model/effort requirements remain unchanged. Current calibration delivers two native PPTX variants and matching marketplace listing CSV/JSON per owner guide v1.1, but no ZIP, guide or preview package; 2026-10-14 PPTX-only wording is historical. A role prompt cannot verify actual model selection or tool availability.

Generic slide requests and explicit Keynote, Google Slides or Figma presentations are valid presentation context; verify actual target tools and dimensions. The executable SDK implements PPTX and typed web decks only. HTML/browser/render/SVG/Figma-reference support remains shared presentation infrastructure, not a standalone website/vector capability. Only an explicit native-plus-web request requires two deliverables and independent receipts.

Native PPTX default physical size applies only to new native PPTX; explicit user size wins, existing source size is preserved unless resizing is requested. Web keeps its own stage contract. Never copy PPTX sizing to other platforms.

Shared memory and historical records are advisory evidence, never executable authorization. Preserve positive and negative history, local pending/unknown/conflicting operations and provenance. Unknown service writes require reconciliation, not blind replay; no missing history or empty evidence establishes originality/visual PASS.

A plan, runtime stage marker, file presence, screenshot presence or technical export does not establish creative readiness. Simulation REVISE/BLOCKED cannot be overwritten by later polish. Main must inspect current actual evidence. When documentation and code disagree, repair both; keep a single active interpretation.

Design Craft is non-override support for presentation work. It cannot replace or weaken owner requirements, cognition, simulation, originality, lifecycle, post-build or completion gates.

Dedicated nondeck products and their source artifacts are recoverably separated outside active source. Mixed shared documents may retain historical examples, but PRESENTATION_SCOPE restricts their activation. Website product defaults/section floors do not apply to slide templates.

Navigation is a derived, advisory source index owned by scripts/design_brain_navigation.py. It supplements context preparation after packet_sources selects mandatory documents; it never controls memory, progress, creative acceptance or host activation. See runtime/TOKEN_EFFICIENT_CONTINUITY.md and registry/navigation.json.

## F01–F09 reconciled implementation map (2026-10-21)

- **Runtime owner:** `scripts/design_brain_runtime.py` retains the 2.9.0 `efficient-v1` state, one per-session `design-brain.checkpoint.v1` slide roster and pilot, atomic saves, `workflowCommands`, host repair-batch stagnation guard, `--session`, `prepare-context` and read-only `resume`. A repeat `start` refuses existing session bytes.
- **Execution evidence:** `run` / `run-next` emit `REQUESTED` for unexecuted stages, and `RECORDED` for a revision-bound external declaration; neither is native observation nor gate PASS. Direct native routing and current verified post-build/final-binding results alone populate `verified_stages`.
- **Repair authority:** `scripts/design_brain_repair_ticket.py` owns issue identity, corrupt-input fail-closed, idempotent changed-input attempts, per-issue accounting, and mandatory reruns after administrative closure. `post_build_pass3` is a layout gate; batch stagnation belongs to the separate canonical checkpoint.
- **Audit/finalizer:** `scripts/design_brain_post_build_audit.py` owns immutable `completion-preparation.json`, `post-build-audit-receipt.json`, `completion-receipt.json` and `auditInputRefs` identities. `scripts/design_brain_visual_gate.py` verifies audit phase, four passes, inputs, fresh visual manifest and artifact identity. `finalize`/verify-final revalidate dependencies; `pending_final` never means delivered.
- **Visual identity:** `scripts/design_brain_visual_inspect.py` owns artifact/order/render/frame/dependency/question/view binding, original observation provenance, a request-scoped cache only, and a separately observed new whole-deck Main overview. Unknown/shared dependencies force a full review.
- **Context and memory:** `scripts/design_brain_context_packet.py` selects the phase's required documents and canonical realpaths; `scripts/design_brain_memory_adapter.py` plus local memory preserve independent Supabase/cache/legacy/outbox origin-qualified revisions and summary-first discovery. Hashes are not model-knowledge or creative-approval evidence.
- **Routing and product scope:** `hooks/brain-design-route.mjs` emits whole absolute paths, including spaces; `.design-brain/PRESENTATION_SCOPE.md` excludes nondeck website/dashboard/landing-page products. PPTX stays primary; host/both are explicit request modes.
- **Integrity and owner rules:** `skills/presentation-deck/provenance/integrity.json` retains its 42 protected source entries and both efficiency/navigation provenance records; `adopted-files.json` preserves donor `sourceSha256`, updates merged adopted hashes only. Fictional/example years start at 2046 (not user/factual/system dates); owner line spacing is unchanged.
