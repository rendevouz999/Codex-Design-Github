# Finite design progress and bounded context

These additive helpers reduce repeated payloads and rediscovery. They do not expand a host allowance, reset used context, guarantee token savings, lower model/effort, add workers, activate services or replace any design gate. Main plus the same single Engineer remain responsible for complete requested output and current evidence.

## Keep the next action executable

Use the existing runtime session as the project controller directory (`start --output-dir <project>`); a new native workspace is a distinct child such as `<project>/native/deck_YYYYMMDD`, so init does not collide with session-state.json. Put source, assets and evidence under it; no duplicate artifact copy is required. Resume an existing project session; `start` refuses to overwrite its state. New efficient-v1 host production requires a checkpoint before Engineer handoff, build/repair/final context preparation, resumed context preparation, or final readiness. Main's first planning context remains available to establish the brief. Legacy, plan-only and explicitly selected SDK sessions retain their existing contracts.

Pass `--expected-slides N` to `start` when the requested roster is established, or initialize it afterward. Use the actual requested count; never silently invent or reduce it. Initialization creates only TODO entries and a pending native pilot, without artifact acceptance. The returned `workflowCommands` expose the active plugin root/version/runtime hash and session-bound initialization, checkpoint and compact commands. A checkpoint input JSON must be under the project directory and at most 128 KB:

```text
python scripts/design_brain_runtime.py checkpoint --session <project> --initialize --expected-slides N --json
```

Update that roster with real state/evidence and save before each handoff, after each coherent build/repair batch, and before compact/resume:

```text
python scripts/design_brain_runtime.py checkpoint --session <project> --file <project>/checkpoint-input.json --json
python scripts/design_brain_runtime.py compact --session <project> --json
```

Checkpoint schema `design-brain.checkpoint.v1` requires:

- `sessionId`: exact session identity; `taskSha256`: SHA-256 of the exact UTF-8 session task
- `expectedSlides`: 1–500; `slides`: complete unique IDs 1..N, each with `status` (`todo`, `authored`, `repair`, `awaiting_main`, `accepted`) and `artifacts` path/SHA-256 pairs
- `dependencies`: explicit lists for `source`, `theme`, `master`, `font`, `image`, `render`, `policy`; include shared assets, font files, renderer/tool configuration, policy and canvas dependencies. Empty lists mean declared empty, never verified completeness
- `pilot`: `status` (`PENDING`, `PASS`, `REVISE`, `NOT_APPLICABLE`), `slideIds` 1..min(3,N), and `evidence` path/SHA-256 pairs. Only Main records real approval. Native creation/substantial redesign still requires the first-three-slide gate; `NOT_APPLICABLE` cannot waive it
- `activeConstraints`: bounded current owner constraints/corrections and rejected directions
- `openRepairs`: target, requestedChange, acceptanceCheck; `unknownOperations`: id, status (`UNKNOWN` or `INTERRUPTED`), reconcile
- `nextAction`: actor (`main` or `engineer`), target, action, expectedOutput, nonempty checks

Paths are relative to the project/session. Public plugin dependencies may use `plugin:<relative-path>`; root escapes, symlink escapes and private plugin credential/store references are rejected. File hashing is streamed and bounded to 256 MiB per file. Checkpoint values are advisory declarations, not visual receipts, memory synchronization, proof of dependency completeness or fresh acceptance. Main still saves/revises canonical shared memory with readback under LOCAL_MEMORY_POLICY; link its record/revision/operation in task notes where useful.

Saving valid partial work succeeds and reports completionPending plus slide counts. Pending slides/pilot/repairs prevent final readiness, but do not prevent useful forward work. Hash changes, missing files and unknown mutations require reconciliation before dependent work; do not replay an uncertain operation. The stored requested slide count cannot silently shrink. Status, compact and finalize recheck current declared file hashes. State replacement is atomic; each efficient-v1 state save refreshes project context-summary.json and compact-context.md plus the current-session mirror. Prefer the project files and verify their session, taskSha256 and stateSha256 against the intended session-state.json before resuming. The canonical JSON retains the full checkpoint, including invalid/unknown data; read its constraints, accepted identities, pilot, repairs and unknown operations. Compact JSON returns a bounded projection with full-read pointers; `compact --full --json` explicitly returns complete details. A failed refresh never establishes fresh evidence.

## Resume and execution evidence (F01–F06)

`python scripts/design_brain_runtime.py resume --session <project> --json` reads the **existing** `design-brain.checkpoint.v1`, not a donor checkpoint schema. It reports CURRENT/STALE/UNKNOWN, remaining/affected slide IDs, real open repairs, pilot, and the next action without rewriting session-state bytes or selecting a global project. Reconcile missing sources/unknown operations before retrying an uncertain mutation.

`run` and `run-next` now separate **REQUESTED** from **RECORDED** external declarations and directly **verified** native tool outcomes. A third-party receipt can preserve ID/revision/operation evidence, but its declaration never automatically passes a production gate. Only the current observed route, validated post-build evidence or current final binding can enter `verified_stages`. Administrative ticket closure does not clear its source-gate rerun debt; the separate per-issue repair-attempt count never replaces the Main-owned `--repair-round` checkpoint stagnation counter.

Closing order: run `design_brain_post_build_audit.py --completion-phase prepare` to write immutable preparation; run `--completion-phase audit` to write an evidence receipt with `auditInputRefs` (actual artifact, source hygiene, design-system, originality, cognition, visual and lifecycle/provenance inputs), and use runtime `run --command /design-post-build --visual-receipt <audit> --build-artifact <pptx>` after actual inspection. Finally call runtime `finalize --session <project>`, which binds the exact current audited inputs to completion and verifies them again. `READY` with `pending_final`/`finalAllowed=false` is **not** final delivery. Any changed/missing declared dependency blocks final binding even when the PPTX file itself is unchanged. A source-only `READY_WITH_LIMITATIONS` remains diagnostic/pending and never establishes final acceptance.

The visual verifier may cache repeated original-manifest checks for only one invocation, rechecking the relevant file hashes before a cache hit. It never fabricates review timestamps or a Main whole-deck contact-sheet observation. A new final Main overview must bind the artifact hash, actual complete slide order, view hash, viewing time, and an explicit continuity assessment.

## Send repairs as deltas

Main assigns slide/slot/object, observed defect, requested change, acceptance check, current source/evidence identities, and what remains accepted. Engineer edits the affected source and shared dependencies, batches independent repairs into one coherent version, and returns changed files plus checks and unresolved questions. Do not rebuild/redesign unrelated slides without cause. A shared theme/master/font/image/canvas/renderer/policy change requires checking every affected slide. Unchanged pilot handling follows PPTX_FIRST_THREE_SLIDES_REVIEW exactly.

Keep each open repair's `target` stable until its actual acceptance check is satisfied. Save `checkpoint --file ... --repair-round` exactly once per completed repair batch. The repair baseline includes checkpoint targets, canonical open-ticket IDs and failed gates. Two consecutive batches that resolve no prior target while repairs remain require Main to inspect the cause and record a concrete changed strategy with `--main-decision "..."` before another Engineer handoff. A decision resets the stagnation counter; it does not close defects, waive gates, or approve output. Image-slot search takeover still follows its own two-rejection policy. This records declared batches; it does not intercept arbitrary host tool calls, meter account quota, or cap total design quality/iterations. Report the actual blocker if no faithful repair route is available.

No creative PASS or Main final approval is copied to another artifact hash. Detail observations may be referenced at their original timestamps only when artifact frame/render/dependencies/context/questions are equivalent and provenance is intact; unknown relationships force actual review. Prior acceptance is a review agenda. Main independently opens every actual final slide, including required overview/detail/context views, and all closing gates/reruns remain mandatory. A stage marker, accepted roster, receipt path or successful export cannot establish completion.

## Keep full tool evidence, print a projection

```text
python skills/presentation-deck/runtime/presentation.py --summary <operation> <arguments>
node skills/presentation-deck/runtime/web/design_brain_deck_source_extract.mjs <source.pptx> --out <evidence-dir> --summary
python scripts/design_brain_memory_adapter.py search "<topic>" --projection summary
python scripts/design_brain_memory_adapter.py list --kind layout_case --projection summary
```

New canonical sessions select `efficient-v1`; returned native prefixes bind `--session` and select summary before the subcommand. Explicit `--full` wins, explicit `--summary` remains supported, and old state/unbound CLI remains legacy full-compatible. Invalid session bindings fail visibly. It preserves operation status, exit/timeout, output identity, input count, diagnostics counts/statuses/IDs and full receipt path. Large diagnostic details/ID lists are explicitly bounded with omission counts; read the full receipt by stream/line IDs for every relevant blocker. Selected invocations save raw stdout/stderr byte snapshots separately before projection, with path/hash/bytes/complete metadata and a same-invocation full receipt. Console tails have omission counts; read the exact stream files/ranges, never rerun for recovery. Output above the combined 64 MiB trigger terminates the process tree, with possible polling overshoot reported as actual bytes. Timeout, output-limit, drain/storage/capture failure is UNKNOWN with incomplete evidence. A missing archive is never promised as full recovery. Unknown parser shapes are labelled UNPARSED, with bounded raw fallback; keyword counts never assert zero errors. The operation can PASS while designReadiness remains NOT_EVALUATED. Source extraction summary preserves coverage, source hash, degradation and affected-slide counts plus full evidence/plan paths; dry runs explicitly have no persisted details. Legacy --json is unchanged and cannot be combined with --summary.

Memory summary preserves separate origins, revisions, review/negative status, sync/conflict state, evidence status/hashes and BOTH next_offset values. It never merges queued/local-only or rejected records away. Page both sources to required coverage, then read full applicable records; active policy, owner corrections and negative constraints cannot be decided from excerpts. Engineer independently retrieves history. Service failures and uncertain operations remain explicit. Summary read pointers identify origin/operation as well as revision; compare all matching returned origins rather than assuming one ID is one truth.

## Phase/hash manifest, without invented model knowledge

Each role uses the returned `prepare-context --session ... --role main|engineer --phase plan|build|repair|final --context-epoch ...` command to persist a manifest by default. Stable instruction/source-order/hash prefix precedes timestamp and changing session body. Direct CLI compatibility remains: add `--manifest-output <json> --context-epoch <caller-epoch> --role main|engineer --phase plan|build|repair|final` to the existing context packet tool. Optionally pass `--previous-manifest <json> --manifest-summary` to print only the loading delta/critical contract/pointers; the full packet and manifest stay in files. A dry-run summary explicitly has no persisted details. Legacy output remains unchanged. Critical contract and applicable full template guide remain required. Design-system authoring requirements and acceptance criteria load before build; no whole mixed policy document is automatically deferred just because it contains post-build instructions. Execution-only detail may be read when its phase starts, without removing final criteria or gates.

Sources deduplicate by canonical path; unconditional reads win over conditional labels. Figma source study and Figma output authoring are selected separately from actual task intent; applicable full guides and every authoring/final gate remain required. Task, role, epoch or source-hash changes request a fresh read. A phase change alone can reuse the same source loading plan within the same retained context. PRIOR_MANIFEST_ONLY means only that a previous loading plan mentioned the same bytes. It is neither a read receipt nor proof the model still remembers the contents. Use a delta only after confirming the source is actually available in the same context; otherwise reload. After host compact/resume/context loss, use a new epoch and reload the critical contract plus normative sources needed for the next action. The plugin cannot detect or control the host's private context or cache.

Offline regression: `python -B scripts/test_design_brain_token_efficiency.py`. This tests continuity/projections with synthetic fixtures, not a completed real deck or measured allowance savings.

## Method-only implementation and reuse contract

The selected methods are implemented here, not loaded as four donor skills. Provenance lives in `skills/presentation-deck/provenance/efficiency-methods.json`; no donor source is copied or installed.

- Ponytail: before edits trace real input → canonical caller → existing function owner → state/config/dependency → output consumer/error → completion evidence. Reuse public APIs, import/export algorithms, data primitives and QA first. Add a function only for a demonstrated gap, in its existing native/web owner, then wire and check its actual callers. No regex codebase map, global hooks/mode tracker, whole-repository debt/gain machinery, LOC/token target, or interpreting an ambiguous brief as the simplest design.
- Caveman: store the original invocation bytes before deterministic projection; preserve code, argv, paths, numbers, exceptions, negation and errors. Separate stable instruction content from changing session state. No source/policy/memory semantic compression, message elision, persona, proxy/server, cache warming/provider hints, model/effort routing or extra workers. Pointers never establish a read or retained knowledge.
- RTK: reduce only known output formats after the original action has the host's required approval and runs. Retain exit/timeout/stream identity, bounded raw fallback, sizes/omissions and same-invocation recovery. No shell rewrite, global PreToolUse wrapper, hidden argv, source/diff/function filtering, arbitrary filter DSL, telemetry/quota meter, proxy or BUSL engine. Reading recovery never reruns a command.
- i-have-adhd: derive one progress representation from current session evidence; report useful result/decision, owner, next action and evidence first. Distinguish observed failure, any explicitly labelled hypothesis and next check. Unknown causes stay unknown. No diagnosis, personal preference, global persona, repeated always-on prompt, five-item limit, or restriction on research, candidate count, deck content or retained information.

Main's bounded Engineer assignment identifies artifact/slide/slot, accepted boundaries, source/evidence identities, expected output and checks. Reuse the same Engineer at the required model and xhigh effort. Technical primitives can be reused across products; a repeated full composition cannot stand in for original design. Concise reporting never reduces evidence collection, requested slides/features, native editability, the pilot, image takeover, both balance gates, originality, final Main review or closing gates. Current PPTX calibration delivers two native PPTX variants (photo and patterned placeholders) plus separate listing CSV/JSON metadata per owner guide v1.1, without a packaging/preview kit.

## One progress projection

`design_brain_runtime.progress_projection()` is the shared owner for runtime status, compatibility status and compact context. It rereads current declared hashes and tickets, recalculates gates/readiness and selects one owner/target/action/output/checks object: reconciliation first, then defects, pilot review/authoring, remaining bounded checkpoint work or the next required gate, and closing readiness. The same action is rendered as a legacy string where required. Compaction retains the full checkpoint, constraints and unknown operations even when malformed; invalid data remains blocked. Projection never closes tickets or grants acceptance. After resume use a new epoch and read the full applicable records.

## Derived navigation, never another authority

The local navigation façade `scripts/design_brain_navigation.py` owns only a deterministic derived index and bounded advisory query. `registry/navigation.json` selects allowlisted public technical source, whole-byte hashing, parser/version limits, lexical aliases and a thin primitive catalog. Source/query output is untrusted data. Mandatory documents, exact task/role/phase/epoch and full applicable reads remain unchanged; graph snippets never replace them or prove retained knowledge. Navigation states CURRENT/STALE/PARTIAL/UNAVAILABLE/CONFLICT are not creative verdicts.

Canonical efficient-v1 prepare-context may refresh this local derived index when explicitly enabled by the shipped configuration. `--navigation off` preserves baseline selection; legacy/direct packet callers remain opt-in. Unavailable/stale/partial/no-match/error navigation falls back without waiving any existing gate. A read-only installation needs an explicitly supplied writable cache directory; no implicit home cache, installation or permission escalation occurs.

Technical cache, project/session pointers and ephemeral memory-discovery views are separate namespaces. Memory metadata is accepted only from an explicit project-confined discovery artifact produced by the existing adapter; navigation makes no automatic network/model call and never scrapes or writes memory. Preserve both origins/cursors and full origin/revision/operation read pointers; read full applicable records independently. Navigation rank cannot bound required history. Root owner_guard.md, secrets, private stores, raw streams, historical reports and generated navigation outputs are excluded from the technical corpus and public package.

Generation publication is lock-protected and atomic; parseComplete and resolutionComplete are explicit. Full source bytes, configuration/parser/resolver versions and root identity determine freshness. Failed/partial scans preserve the last good generation but cannot call its pointers current. No auto-cleanup, watcher, graph stage, ticket closure, hidden host mutation or automatic re-extraction of binaries. Optional Markdown/Canvas export is deferred; no Obsidian app/plugin is required. Technical primitives remain reusable while product compositions stay subject to current originality and Main review.
