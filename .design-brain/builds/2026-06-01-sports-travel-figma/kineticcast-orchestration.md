- premium: polished visual language, precise spacing, modern typography, Apple-like restraint. Marketplace note: Core quality layer for sellable, polished, high-value template products.
- clean: simplicity, whitespace, legibility, limited palette. Marketplace note: Safe foundation for editable templates and broad buyer appeal.
- spacious: generous whitespace, consistent padding, breathable composition, readable layouts. Marketplace note: Prevents AI-like clutter and improves marketplace presentation quality.
- storytelling: narrative flow, emotional journey, guided sections, campaign structure. Marketplace note: Useful for section order, homepage flow, and conversion-focused template storytelling.
- bento: modular grids, card systems, scannable sections, feature blocks. Marketplace note: Useful for product previews, section overviews, and reusable card-based template sections.

### Conflicting Styles To Avoid

- Do not combine too many dominant moods.
- Dashboard should not dominate wedding/event landing pages.
- Perspective is mainly for preview/presentation unless the UI itself needs depth.
- Storytelling should guide structure, not make every UI playful.
- Presentation Deck Pack should use slide-role matrix, not landing-page section order.
- UI Kit System Pack should prioritize state coverage and usage rules over dramatic visuals.
- Brand Kit Pack should define identity application rules, not only attractive mockups.
- Clean/Spacious can be combined with nearly everything.
- Premium/Professional should guide quality and restraint.

## Generic Output Risks

- Using a generic hero that does not signal the niche in the first viewport.
- Making the visual style look polished while the underlying template structure is thin.
- Letting minimalist, safe, fallback, clean, simple, restrained, or basic language justify fewer than 8 website/landing sections.
- Adding decorative effects that do not support buyer decision-making.
- Leaving editable placeholders unclear or inconsistent.
- Using a Figma reference as a flat mood board without a schema receipt or product-standard inference.
- Building Figma template structure as manual x/y placement instead of real auto-layout.
- Using too many TypeUI-derived moods at once instead of a focused style strategy.
- Treating visual style as product strategy instead of defining buyer, use case, and reusable value.
- Overusing perspective mockups so the actual template becomes hard to inspect.
- Turning narrative flow into too many long sections instead of a crisp conversion path.
