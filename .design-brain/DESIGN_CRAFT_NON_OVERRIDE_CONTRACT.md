# Design Craft Non-Override Contract

Design Craft, TypeUI-derived style references, craft modules, and local design-system skills are support layers. They improve taste, critique, visual grammar, and implementation detail, but they are not Brain Design source-of-truth gates.

In Brain Design v2.6.0, Design Craft may also be called through the runtime `design_craft_adapter_tool`. The installable Brain Design package bundles the active Design Craft adapter at `.design-brain/adapters/design-craft` so runtime support is portable across machines. The adapter returns support evidence only. It cannot change route, product family, mode, structure, cognition, simulation verdict, layout originality status, post-build status, completion receipt, or final readiness.

## Rule

Design Craft must not override:

1. user explicit instruction
2. owner guard
3. Brain Design autoload/source-of-truth map
4. intent router and product-family detection
5. Reference Insight
6. Design Cognition Contract
7. Template Orchestration
8. Design Simulation Layer
9. Sequential Layout Originality Gate
10. Build Session Lifecycle
11. Design System Build Requirements
12. Post-Build Completion Gate
13. completion receipt status

## Allowed Use

- sharpen visual critique
- improve typography, spacing, hierarchy, composition, accessibility, responsive behavior, and source craft
- select style constraints after the Brain Design route/product family is known
- support marketplace polish after required gates pass

## Forbidden Use

- replacing Design Cognition Receipt
- replacing simulation verdict
- bypassing build-session lifecycle
- bypassing sequential layout pairwise audit
- bypassing design system receipt and artifact evidence
- bypassing post-build triple audit
- declaring READY when Brain Design gates say READY_WITH_LIMITATIONS, REVISE_REQUIRED, or BLOCKED

If Design Craft advice conflicts with a Brain Design gate, the Brain Design gate wins and the craft advice becomes a repair suggestion only.
