# Layout Fluidity Expansion

This file turns the user's critique `kaku` into a practical Brain Design gate.

`Kaku` means the template may look polished in isolation but still feels stiff, boxed, over-regular, or too similar to earlier outputs because the layout gesture repeats.

This is not a request for chaos. A premium template can be calm and still fluid. Fluidity means the page has a distinctive spatial idea, controlled movement, varied section silhouettes, and product-fit composition logic.

## What Layout Stiffness Looks Like

Common symptoms:

- every section is a centered rectangle stack
- hero always follows text-left/media-right or media-left/text-right
- every module sits in the same 3-card or 4-card grid
- all sections have the same width, same top padding, same heading placement, same card anatomy
- proof, pricing, FAQ, CTA, and footer always arrive in the same visual rhythm
- image placeholders use the same crop shape and alignment across templates
- the page has no memorable spatial move beyond color or copy
- different templates share the same visual silhouette when zoomed out
- the layout has no controlled tension: no offset, overlap, sidebar, rail, split density, editorial crop, step-down rhythm, diagonal cue, asymmetry, or focal-path shift

If template A/B/C/D/E/F can be recognized as siblings by their silhouette before reading content, Brain Design must treat this as layout stiffness.

## Layout Fluidity Axes

Every substantial template plan should define these axes before build:

1. `layoutGesture`
   - The main spatial movement: editorial rail, staggered proof path, dashboard shell, split ledger, diagonal journey, full-bleed gallery, product stage, timeline spine, asymmetric collage, document stack, radial/spotlight focus, masonry browse, or another named gesture.

2. `sectionSilhouettes`
   - The visible shapes of major sections when zoomed out: masthead, shelf, runway, ledger, split-stage, magazine well, long-form article, card deck, sidecar, table console, gallery wall, vertical timeline, map panel, comparison strip, pricing island, form drawer, or footer slab.

3. `compositionTension`
   - How the layout avoids dead symmetry while staying controlled: offset columns, asymmetrical weight, overlap, cropped media, vertical rail, anchored sidebar, reversed density, compressed proof beside spacious copy, split background, edge-aligned media, or intentional quiet.

4. `focalPath`
   - Where the eye moves first, second, and third. This must change between batch outputs unless the product family explicitly requires the same path.

5. `negativeSpaceShape`
   - The shape and function of empty space: runway, margin well, editorial pause, product breathing room, proof separation, luxury calm, technical clarity, or scan buffer.

6. `depthLayering`
   - How foreground/background, overlays, shadows, media planes, panels, or flat layers create depth. Deliberate flatness is valid only when it is named and hierarchy still works.

7. `moduleScaleVariation`
   - How repeated content changes scale: large-small alternation, mixed card sizes, hero-to-detail compression, feature/proof contrast, dense row after open stage, or uniform grid by deliberate need.

8. `breakoutBehavior`
   - How sections break the container rhythm: full-bleed band, inset island, side rail, sticky form, horizontal strip, overlap bridge, floating proof, diagonal/cropped break, or intentional no-break restraint.

9. `sectionPatternMix`
   - Which stable section-layout catalog patterns are used, where they appear,
     which density limits they enforce, and how this mix diverges from previous
     accepted templates.

These axes must appear in the layout fingerprint for reference-led, batch, marketplace, Figma/source, and full website-template work.

## Layout Exploration Menu

Before selecting a final structure, explore at least three families of layout gesture when the task is substantial or when previous outputs risk similarity:

- Editorial: masthead, magazine rail, side notes, pull quotes, feature wells, captioned image rhythm.
- Operational: dashboard shell, command center, map/table hybrid, task queue, status console, filter panel.
- Commerce: product stage, category browse, lookbook grid, comparison shelf, cart-confidence strip.
- Service/booking: form-first split, path selector, trust ledger, appointment timeline, contact drawer.
- Hospitality/lifestyle: full-bleed image pause, itinerary/story path, gallery wall, package island, map closure.
- Finance/business: proof ledger, advisory matrix, report card, timeline sprint, evidence-before-CTA.
- Creative/portfolio: case-study runway, asymmetric collage, process spine, studio board, manifesto band.
- Tech/AI: signal console, system diagram, dark stage, data stream, integration map, security/proof strip.

Do not pick from the menu mechanically. Use it to escape the first safe layout idea.

## Reference Layout Remix Rule

When Codex runs out of layout ideas, it may use the selected references as a shape bank, but not as a direct mold.

Allowed:

- borrow one reference's section silhouette, another reference's module rhythm, and a third reference's focal path, then recombine them into a new product-specific structure
- translate a reference split, rail, shelf, table, gallery, process spine, drawer, or footer idea into a different category-appropriate action model
- use reference evidence to raise structure depth, shape variety, and craft standard

Forbidden:

- copying a full reference section with only color, copy, or spacing changes
- using one reference layout as the page scaffold for every output
- repeating the same borrowed shape in multiple templates in the same batch
- claiming originality when the reference's zoomed-out silhouette is still obvious

Premium remix is subtle: the new section may inherit the reason behind the reference shape, but its proportions, grouping, content logic, visual motif, and action model must be original.

## Pre-Build Fluidity Check

Before building, answer:

- What is the memorable layout gesture?
- Which section silhouette must not repeat from previous templates?
- Where does the page intentionally break symmetry?
- What is the focal path?
- What shape does the negative space create?
- Which module changes scale or rhythm?
- What is the breakout moment?
- Which section catalog patterns are being used, and which prior pattern mix is avoided?
- Which previous accepted layout gesture is this design moving away from?

If the answers are generic, the plan is not ready.

## Batch Fluidity Gate

For template 2 and later, compare against every accepted earlier template:

- Same `layoutGesture` is a hard risk.
- Same section silhouette sequence is a hard risk.
- Same title/media/card/focal path is a hard risk.
- Same negative-space shape across the page is a soft risk that becomes hard when paired with similar grid or rhythm.
- Same breakout behavior plus same card cadence is a structure similarity defect.

Repair depends on root cause:

- If layout gesture repeats, rebuild the newer template's spatial concept.
- If only one section silhouette repeats, recompose that section.
- If grid is different but the page still feels stiff, add controlled asymmetry, scale contrast, focal-path change, or a new breakout moment.
- If the product category requires restraint, document deliberate restraint and prove hierarchy through spacing, type, proportion, and section contrast.

## Do Not Overcorrect

Fluidity is not random complexity.

Avoid:

- decorative zigzags with no buyer purpose
- arbitrary overlaps that hurt editability
- asymmetry that breaks source-template usability
- too many section shapes in one page
- breaking auto-layout just to look expressive
- making every template loud

Good fluidity is controlled, editable, and commercially useful.

## Completion Standard

A template can be called layout-fluid only when:

- it has a named layout gesture
- section silhouettes vary enough to avoid a stiff vertical stack
- composition has controlled tension or intentional restraint
- the focal path is clear
- at least one section meaningfully breaks the page rhythm
- it does not feel like a sibling of prior accepted templates
- the source remains editable and product-ready
