## What PowerPoint Templates Are Optimizing For

1. Fixed slide canvas, not scrolling responsiveness.
   Most PPTX decks use 16:9 canvases. Some are standard wide `13.33 x 7.50 in`; many marketplace Google Slide exports use a larger wide canvas around `21.99 x 12.37 in`. The design must work as a projected frame and as a thumbnail, not as a long responsive web page.

2. Deck sequence, not landing-page funnel.
   A PowerPoint template is a story kit: cover, agenda, divider, company intro, problem, solution, service, market, timeline, metrics, team, chart/table, quote/testimonial, contact, closing. Website sections can scroll into each other, but deck slides must stand alone and still feel related.

3. Layout system is the product.
   Strong decks contain repeated slide roles and reusable arrangements. The value is not only the visual mood, but the editable role inventory: title slide, split image slide, metric slide, roadmap slide, portfolio/gallery slide, rate card slide, team slide, risk slide, finance/fund slide, and thank-you slide.

4. One main idea per slide.
   Good slide templates use composition to reveal one idea quickly. Dense decks can include business-plan detail, but the text must be grouped into clear blocks, callouts, bullets, or tables. Long paragraphs reduce slide quality faster than they do on web pages.

5. Design system must include presentation-specific rules.
   A deck design system needs colors, typography, spacing, radius, image treatment, chart palette, table style, icon style, callout style, footer/page-number rules, divider rules, and placeholder behavior. Web-only states such as hover, nav dropdown, or breakpoint behavior are secondary unless the final output is interactive.

## Observed Archetypes

1. Modern project proposal.
   Blue/lime/cream accent palettes, 20-slide structure, about/project/detail/innovation/service/audience/problem/solution/strategy/team/closing. Best insight: strong accent color can carry a proposal deck when it is reserved for markers, highlights, and action surfaces.

2. Dense business plan.
   Black, gray, green, orange, and lime palette with many text blocks, metrics, roadmap, risk, management, and fund allocation. Best insight: business-plan templates need compact information architecture, not decorative hero thinking.

3. Shape-driven awareness deck.
   Blue/yellow zero-waste deck uses many layout variants and almost no media. Best insight: a deck can feel complete through a strong shape grammar, repeated color fields, and varied text arrangements.

4. KOL or talent proposal.
   Green/purple/black deck uses profile cards, social handles, rate card, benefits, and contact slides. Best insight: presentation templates for people/services need profile, proof, offer, pricing, and booking logic.

5. Image-heavy brand or pitch deck.
   Keynote files include many embedded JPG assets. Best insight: brand decks need a stricter photo treatment system, not only typography and colors.

6. Minimal portfolio deck.
   White/black portfolio uses low text, high whitespace, many layout variants, and gallery-like slide roles. Best insight: portfolio decks should behave like an edited catalog, not a conversion landing page.

7. Retro proposal deck.
   Orange/red/pink proposal deck is dense and expressive, with chart support and heavy typography. Best insight: expressive decks need tighter alignment and type hierarchy so retro energy does not become visual noise.

8. Premium project proposal.
   White/gold/blue-gray project proposal uses more media, project details, timeline, risk, metrics, and team. Best insight: image placeholders and metric callouts are core editable assets for proposal decks.

## PowerPoint vs Website / Landing Page

- Website: vertical scroll, responsive sections, navigation, conversion CTA, interactive states, SEO-readable copy, repeated cards across breakpoints.
- PowerPoint: horizontal slide sequence, fixed frame, narrative order, role-based slide layouts, projection readability, thumbnail clarity, editable placeholders, speaker-friendly density.
- Website hero: first viewport sells the product immediately.
- PowerPoint cover: opens a story and establishes theme; it does not need to contain all value propositions.
- Website design system: buttons, forms, nav, cards, breakpoints, hover/focus states.
- PowerPoint design system: masters/layouts, title positions, safe margins, footers, slide numbers, chart colors, table styles, callout shapes, image masks, section dividers.
- Website originality risk: same section order and card compositions.
- PowerPoint originality risk: same slide sequence, same title placement, same master structure, same decorative motif, and same role-to-role rhythm.

## Figma Execution Rules For Future Deck Templates

- Build each slide as an individual 16:9 frame.
- Use a slide grid/contact-sheet page for overview, not one long landing-page artboard.
- Create a design-system frame with role tokens: color, type, spacing, shape, image, chart, table, footer, and slide-number rules.
- Use auto-layout inside slide regions only where it improves editability: title groups, bullet stacks, metric rows, profile cards, agenda rows, pricing/rate cards, and contact blocks.
- Avoid website navigation bars, FAQ sections, long CTA bands, and scroll-section logic unless the deck topic explicitly needs them.
- Define 6 to 10 core slide roles before decorating.
- Check every slide at thumbnail size; the primary title and visual idea must remain readable.
- Do not copy reference slide order. Reinterpret mood through new role order, new composition logic, and new placeholder strategy.

## Rules To Reuse

- Start presentation templates from a slide-role matrix, not from a web section map.
- Use one dominant idea per slide and one dominant hierarchy path.
- Keep safe margins consistent across the deck.
- Treat charts, tables, numbers, and footers as part of the design system.
- Use image placeholders intentionally: full-bleed, masked, gallery, profile, or case-study treatment.
- Let every deck style have a signature grammar: shape language, title alignment, color placement, and transition rhythm.
- If building PowerPoint inside Figma, the Figma output should feel like a real editable deck, not a resized website page.
