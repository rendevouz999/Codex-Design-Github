## Seed Lessons

### Landing Page Template Batch

- Medium: Website / Figma template.
- Product type: Landing page.
- Niche: Mixed commercial templates.
- Good pattern: Each template uses a distinct first structural move and section rhythm.
- Bad pattern: Four templates share the same hero, proof, service, CTA order with only color/copy changes.
- Why it works or fails: Batch value comes from diversity of layout grammar, not superficial variants.
- Reusable rule: In a batch, assign a different archetype, hierarchy anchor, and content rhythm to each product.
- Do-not-copy: Repeated section order and repeated hero composition.

### PowerPoint Proposal Template

- Medium: Presentation deck.
- Product type: Project proposal or pitch deck.
- Niche: Business proposal.
- Good pattern: Uses slide-role matrix, safe margins, chart/table rules, and reusable title placement variants.
- Bad pattern: Looks like a long landing page broken into slides.
- Why it works or fails: Deck buyers need reusable presentation scenarios, not a single scrolling story.
- Reusable rule: Start presentation products with slide roles and master/layout rules.
- Do-not-copy: Same slide sequence, same title placement, same decorative motif.

### Marketplace Cover

- Medium: Marketplace preview.
- Product type: Template cover.
- Niche: Any template product.
- Good pattern: Shows real product surfaces flat enough to inspect, then uses perspective as support.
- Bad pattern: Beautiful mockup wall that hides actual template quality.
- Why it works or fails: Buyers need proof of completeness and editability.
- Reusable rule: Cover must sell and reveal the product at the same time.
- Do-not-copy: Cover compositions that obscure the actual template.

### Website Template Corpus

- Medium: Website / Figma / PSD / XD template corpus.
- Product type: Mixed website templates, including landing pages, ecommerce, dashboards, portfolios, newsletters, mobile screens, and hero kits.
- Niche: Mixed commercial website products.
- Good pattern: The template subtype controls the structure: ecommerce needs product discovery, dashboards need operational states, portfolios need visible work, newsletters need email-safe modular blocks, and landing pages need conversion flow.
- Bad pattern: Treating every website-adjacent asset as the same hero/features/proof/pricing/CTA landing page.
- Why it works or fails: Buyers judge templates by product fit and editability. A visually polished page still feels generic when the structure ignores the subtype.
- Reusable rule: Diagnose the website subtype before style selection, then choose subtype-specific evidence, modules, and responsive behavior.
- Do-not-copy: Same landing-page section order, repeated split-hero composition, generic bento cards, and visual mood changes without structural reinterpretation.

### Layout Stiffness In Template Batch

- Medium: Website / Figma template.
- Product type: Batch template output.
- Niche: Any commercial template set.
- Good pattern: Each template has its own layout gesture, section silhouette sequence, focal path, and rhythm break. One might use an editorial rail, another a dashboard shell, another a product-stage gallery, and another a timeline/ledger path.
- Bad pattern: Templates A/B/C/D/E/F all use stacked centered sections, split hero, proof strip, card grid, pricing cards, FAQ, CTA, and footer, with only color and copy changes.
- Why it works or fails: Buyers and reviewers judge similarity from the zoomed-out silhouette before reading copy. Repeated shape grammar makes the work feel stiff even if every individual template is clean.
- Reusable rule: Before build, name the layout gesture and section silhouettes. For batch items after the first, compare those axes against all accepted templates and rebuild the newer plan if they repeat.
- Do-not-copy: Same spatial gesture, same section silhouettes, same title/media/card balance, same negative-space shape, and same breakout behavior.
