# Figma Reference Learning Corpus

This corpus stores user-provided Figma template references used to train Design Brain's professional template reading habit.

Use these links as learning material, not as reusable scaffolds. For each actual build, inspect the selected reference again and complete `.design-brain/FIGMA_PROFESSIONAL_TEMPLATE_LEARNING.md` plus `.design-brain/templates/FIGMA_REFERENCE_SCHEMA_RECEIPT.md`.

## User Goal

Find the thinking pattern of a professional designer who avoids default minimalist reasoning while still producing premium template products.

The desired learning target is:

- product purpose before style
- niche-specific structure before generic sections
- visual direction without copying
- grid, spacing, typography, color-role, image, component, content, responsive, and Figma-source logic
- original reconstruction from system understanding

## Access And Evidence Notes

- Shopify Landing Page Concept was accessible enough to inspect page metadata. Observed: `Page 1`, main frame `Shopify Landing Page Concept`, 1440 wide by 7085 tall, with named header/nav/product/article/marquee/footer-like sections. Reusable lesson: ecommerce/retail references may use long editorial product storytelling, not just hero plus cards.
- Indekstore Finance Display was accessible enough to inspect page metadata. Observed: `01 Homepage`, main frame `32-04-Indekstore-Finance-Display`, 1440 wide by 4399 tall, with named sections `01-navbar`, `02-hero-image`, `03-section`, `04-section`, `05-Product`, `06-Banner`, and `07-footer`. Reusable lesson: finance references often use trust, benefit, risk, product, banner CTA, and structured footer logic.
- Mivara initial access exposed a `Cover` page only. Before using it as execution reference, inspect additional pages/frames or mark evidence as partial and use hospitality category standards.
- The Iso luxury real estate link appeared twice in the user-provided material. Keep one unique reference entry and inspect it per build when selected.

## How To Use This Corpus

1. Pick only references relevant to the current product family.
2. Do not average all references into one generic structure.
3. Inspect the selected Figma files/pages/frames when access is available.
4. Complete the professional reading order: product purpose, visual direction, section map, grid, typography, color roles, image direction, components, spacing, signature, content logic, responsiveness, and Figma hygiene.
5. Produce a new template identity and structure fingerprint.
6. Record what was learned and what must not be copied.

## Do Not Use As

- a shared scaffold for all future templates
- a color palette library to copy
- proof that every template should be minimalist
- proof that every website is a landing page
- permission to skip category-specific pages, components, states, responsive behavior, or Figma source hygiene
