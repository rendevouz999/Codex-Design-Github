# Designer Cognition Layer

Use this layer before creating, reviewing, or revising any reference-based or batch template product.

The purpose is to learn how a human designer is thinking, not to extract a surface layout. Codex must explain why a visual decision exists, what it does to the viewer, what commercial function it serves, and how the thinking can be transformed into an original execution.

## Core Rule

Do not ban abstract reasoning patterns. Ban recognizable execution patterns.

Reusable abstract logic is allowed:

- trust-before-pricing logic
- calm-to-dense rhythm logic
- evidence-before-action logic
- visual proof logic
- attention flow logic
- buyer confidence logic
- progressive disclosure
- simplify-after-complexity logic
- enrich-where-proof-is-needed logic

Recognizable execution is not allowed:

- exact composition
- exact pacing
- exact section treatment
- exact component grouping
- exact image placement
- exact visual motif
- exact distinctive CTA staging
- same hero grammar plus same mid-page rhythm plus same conversion closure

The mental move can transfer. The visible move must be transformed.

## Buyer Decision Model

Before analyzing designer cognition, identify the marketplace buyer and the end user.

Answer these before design work starts:

- Who buys this template?
- Who is the end audience inside the design?
- What does the buyer need the template to prove?
- What makes the template feel complete for its product type?
- What makes the template commercially useful and easy to adapt?
- What would make the buyer reject it as too generic, too empty, too similar, or hard to customize?

A marketplace template must convince both the buyer who purchases the template and the end user who experiences the final design.

## Cognition Ladder

Analyze each selected reference with this ladder:

1. Surface Observation: what is visibly present?
2. Decision Hypothesis: why might the designer have made that decision?
3. User Effect: what does it make the viewer feel, understand, trust, or do?
4. Business / Product Function: how does it support the template goal?
5. Repeated Designer Pattern: does this decision repeat across multiple references?
6. Reusable Thinking Logic: what abstract logic can be reused without copying?
7. Original Transformation: how can the logic be expressed with different visuals, layout, components, and rhythm?

Do not stop at labels such as clean, modern, restrained, premium, bold, elegant, hero, feature, card, or CTA. Those are surface labels, not cognition.

## Color Cognition

Color is part of designer cognition, but reference color must be interpreted rather than copied.

When a reference uses a strong palette, identify the function behind the palette before selecting new colors:

- Does it create calm, urgency, trust, luxury, warmth, technical confidence, operational focus, or playful energy?
- Does the accent guide action, mark proof, separate surfaces, signal data, or create category recognition?
- Does the background make content feel premium, readable, cinematic, clinical, editorial, or utility-first?
- Would copying the same palette make the output look derivative or category-correct?

The new template may use an assumed palette if the assumption is grounded in product type, buyer expectation, marketplace category, accessibility, and the intended viewer effect. The palette should preserve the learned function, not the reference appearance.

State the decision as: reference color function -> reconstructed palette role.

## Evidence Layer

Every designer-cognition claim must include evidence. Do not make strong claims without visible evidence.

Use this record format:

- Observed evidence:
- Inferred designer reason:
- User or buyer effect:
- Business or product function:
- Reusable thinking logic:
- Originality transformation:
- Confidence: high / medium / low

Confidence rules:

- High: the visual evidence strongly supports the inference.
- Medium: the evidence suggests the inference but another reason is plausible.
- Low: the inference is useful but weakly evidenced; do not build a major design decision on it alone.

## What To Explain

For each reference or reference group, explain:

- why the designer uses calm or density
- why the designer changes rhythm
- why proof appears where it appears
- why the designer uses image, dashboard, typography, icon, whitespace, or data
- why one section is visually loud and another is quiet
- why the template feels complete instead of flat
- when the designer slows the viewer down
- when the designer pushes toward action
- when the designer uses visual proof instead of text
- when the designer simplifies or enriches

## Reference Pools

When many references are available, use two pools:

For website-template work, use the configured local preview-image corpus, such as `<LOCAL_REFERENCE_CORPUS>/Template Website`, after classifying the product family. Do not make structure or market-depth claims from assumption when product-type-matched local references exist.

### Pattern Learning Pool

Use all relevant references to detect repeated designer thinking patterns: attention flow, proof timing, density changes, image logic, trust strategy, CTA pressure, and buyer confidence moves.

### Execution Influence Pool

Use one active product-purpose reference group to guide one specific output direction. When the local selector has enough matching candidates, that group should contain up to 10 varied references. This prevents both averaged blandness and repeated top-3 stiffness.

## Batch Pattern Memory

For each template cycle, record:

- opening strategy
- hero grammar
- trust strategy
- density rhythm
- component system
- CTA logic
- visual motif
- storytelling arc

The next template must avoid repeating at least 90 percent of the previous cycle's recognizable execution pattern. If two batch outputs share the same opening strategy, hero grammar, component system, rhythm map, and CTA logic, the batch has failed even if colors, copy, and niche are different.

For strict batch audits, compare the current template against every accepted prior fingerprint. If similarity reaches 10 percent, rebuild the current template and keep the earlier accepted template as the fingerprint.

## Readiness Gate

Codex is not ready to design until it can answer:

1. What product type is this?
2. Who buys this template, and what must it prove?
3. What is the designer trying to make the viewer feel or believe?
4. Where does attention go first, second, and third?
5. Where is the design calm, dense, bold, quiet, technical, persuasive, or premium, and why?
6. How does the reference build credibility?
7. What color functions can be learned, and how will the new palette reconstruct them without copying?
8. Where does it add detail, remove detail, slow the viewer down, or push toward action?
9. Why are the components used, not only what components are used?
10. What decision patterns repeat across the Pattern Learning Pool?
11. What exact visual parts must not be copied?
12. What thinking pattern can be reused safely?
13. How will the new template express that thinking with different visuals, layout, components, rhythm, color roles, and CTA logic?

If these answers are weak, stop and repair the cognition before designing.
