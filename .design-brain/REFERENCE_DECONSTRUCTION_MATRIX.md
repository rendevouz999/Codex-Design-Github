# Reference Deconstruction Matrix

Use this matrix when the user gives a design reference, template file, screenshot, Figma link, deck, or website. A reference is a teacher, not a blueprint.

## Required Deconstruction

For each reference, identify:

| Layer | What To Extract | What Not To Copy |
| --- | --- | --- |
| Intent | What the reference is trying to sell, explain, or enable. | The same product promise if the new template has another buyer. |
| Audience | Who the design seems built for. | The same persona assumptions without checking the new niche. |
| Visual mood | Energy, restraint, density, imagery, and emotional tone. | Exact palette, motifs, decorative tricks, or surface treatment. |
| Color system | What colors are doing for emotion, hierarchy, trust, CTA pressure, proof, surface separation, and category fit. | Exact hex values, full palette, gradient sequence, glow color, or the same accent/CTA/background roles. |
| Hierarchy | What gets attention first, second, and third. | Same title placement, same scale jumps, same focal object. |
| Layout grammar | Grid, asymmetry, columns, overlaps, bands, cards, or slide roles. | Same composition and spacing rhythm. |
| Effect language | Shadow, glow, blur, overlay, glass, gradient wash, hairline borders, and surface depth. | Exact shadow values, glow color, blur intensity, or surface treatment. |
| Content flow | How the story moves from entry to proof to action. | Same section order or slide sequence. |
| Editable system | Which parts are reusable or placeholder-friendly. | Flattened visual objects that make future edits hard. |
| Marketplace value | Why a buyer would pay for it. | Same naming, cover structure, or preview staging. |

## Designer Cognition Evidence

For every important claim, capture:

| Evidence Field | Prompt |
| --- | --- |
| Observed evidence | What is visibly present in the reference? |
| Inferred designer reason | Why might the designer have made that decision? |
| User or buyer effect | What does the decision make the viewer feel, understand, trust, or do? |
| Business or product function | How does the decision support the template's commercial goal? |
| Reusable thinking logic | What abstract logic can transfer without copying the visual? |
| Originality transformation | How can the logic be expressed differently? |
| Confidence | high / medium / low |

## Designer Cognition Ladder

Use this ladder before turning a reference into a template plan:

1. Surface observation.
2. Decision hypothesis.
3. User effect.
4. Business or product function.
5. Repeated designer pattern.
6. Reusable thinking logic.
7. Original transformation.

Do not treat words like clean, modern, restrained, premium, hero, feature, card, and CTA as final analysis. Explain why the designer uses calm, density, proof, contrast, image, whitespace, type, dashboard previews, icons, or action pressure.

## Reinterpretation Moves

Choose at least three when designing from a strong reference:

- Change the first structural move: centered hero becomes editorial split, split hero becomes layered proof stack, deck cover becomes role-grid opener.
- Change rhythm: dense-to-open, open-to-modular, modular-to-editorial, editorial-to-operational.
- Change hierarchy anchor: image-led becomes type-led, type-led becomes proof-led, proof-led becomes workflow-led.
- Change grouping: cards become rows, rows become timeline, timeline becomes side rail, side rail becomes gallery.
- Change color role: blue technical trust becomes graphite plus amber signal, beige luxury calm becomes ink plus porcelain highlights, green proof becomes violet analytic markers, or bright CTA becomes restrained high-contrast command.
- Change media strategy: photo collage becomes single hero image, mockup wall becomes flat inspection frames, full-bleed image becomes masked editorial crop.
- Change effect strategy: heavy shadow becomes hairline depth, red glow becomes cyan signal, flat premium becomes subtle floating panel, glass becomes crisp bordered surface.
- Change system artifact: website sections become slide roles, slide roles become dashboard states, brand mood becomes token and layout rules.

## Copy Risk Checklist

- Same section order or slide order.
- Same hero title placement.
- Same image placement or mockup angle.
- Same component grouping.
- Same spacing rhythm.
- Same exact palette, gradient sequence, or color accents in the same roles.
- Same decorative motif.
- Same shadow, glow, blur, overlay, or surface-depth behavior.
- Same naming metaphor.
- Same preview/cover composition.

If three or more are true, redesign the structure before final delivery.
