# Visual Critique Checklist

Score each category from 1 to 10.

If review evidence fails, use `.design-brain/QUALITY_GATE_FAILURE_TAXONOMY.md`. Do not claim visual similarity, render quality, spacing quality, or screenshot inspection unless a screenshot, render, browser view, or Figma screenshot was actually inspected.

- 1-3: weak, confusing, unfinished, or visually untrustworthy.
- 4-6: acceptable but generic, inconsistent, or not yet polished.
- 7-8: strong and usable with minor refinement needed.
- 9-10: premium, intentional, coherent, and marketplace-ready.

## Scoring Rubric

| Category | Score | What To Check |
| --- | --- | --- |
| Hierarchy | /10 | Is the primary focal point obvious? Does secondary content support it? |
| Spacing | /10 | Is whitespace intentional, consistent, and breathable without feeling empty? |
| Typography | /10 | Is the type scale clear, readable, and appropriate for the content density? |
| Alignment | /10 | Do edges, grids, columns, and content groups line up cleanly? |
| Composition balance | /10 | Do sections, previews, text groups, and negative space feel balanced? |
| Brand consistency | /10 | Do visual choices match the intended brand, mood, and audience? |
| Contrast | /10 | Are text, controls, and key content legible with enough contrast? |
| CTA visibility | /10 | Is the main action easy to find and visually distinct? |
| Reference standard evidence | /10 | Did the plan extract section count, section roles, density, layout-shape inventory, color roles, effects, gradients, and marketplace depth from the reference before building? |
| Layout shape exploration | /10 | Does the output explore product-fit shapes from the reference bank without copying the reference silhouette or repeating earlier templates? |
| Color relationship | /10 | Does the palette prove that the chosen A+B or A-G color role map works for hierarchy, mood, contrast, CTA, and differentiation rather than feeling flat? |
| Visual consistency | /10 | Are colors, spacing, radius, shadows, icons, and states coherent? |
| Effect judgment | /10 | Do shadows, glow, blur, overlays, borders, and depth support hierarchy and polish without copying or clutter? |
| Gradient logic | /10 | Do gradients have a hierarchy, mood, material, signal, or conversion role instead of acting as filler? |
| Surface depth | /10 | Are flat, raised, inset, glass, shelf, console, or product-stage surfaces chosen deliberately and applied consistently? |
| Visual-language fingerprint | /10 | For multi-template work, are color roles, effects, gradients, surface depth, CTA behavior, and media treatment distinct from prior accepted outputs? |
| Responsiveness | /10 | Does the layout adapt cleanly across mobile, tablet, and desktop? |
| Figma auto-layout | /10 | For Figma source templates, are editable sections and repeated modules built with real auto-layout and documented exceptions? |
| Per-template design-system separation | /10 | For multi-template Figma/source packs, does each template have its own physically separate design-system frame/page/section instead of one combined board? |
| Output tidiness before delivery | /10 | Are changed frames screenshot-inspected and repaired for clipping, cramped spacing, misalignment, rough hierarchy, and label overflow before final response? |
| Figma reference schema | /10 | If a Figma reference was used, did the plan inspect pages, frames, sections, components, variants, states, and product standard before designing? |
| Figma professional reading | /10 | If a Figma template reference was used, did the plan read product purpose, visual direction, section structure, grid, typography, color roles, image direction, components, spacing rhythm, signature, content logic, responsive behavior, and Figma source hygiene before designing? |
| Accessibility | /10 | Are contrast, focus states, semantics, hit areas, and readability handled? |
| Marketplace quality | /10 | Does it feel polished enough for a Figma/template marketplace presentation? |
| Emotional direction | /10 | Does the design mood match the audience, brand, and purpose? |
| Medium fit | /10 | Does the structure fit the target medium, such as website, deck, dashboard, UI kit, brand kit, or preview? |
| Generic risk | /10 | Does the work avoid interchangeable AI-looking patterns and generic section stacks? |
| Originality risk | /10 | Does it avoid reference copying in order, composition, rhythm, motif, and grouping? |
| Batch fingerprint separation | /10 | For multi-template work, is this output structurally closer to its own selected reference insight than to any accepted previous template? |
| Similarity root-cause accuracy | /10 | If similarity exists, was it correctly diagnosed as structure, composition, effect, visual-language weakness, color-only, or copy/naming-only before revising? |
| Human craft | /10 | Does it show intentional tension, rhythm variation, restraint, and buyer-specific design judgement? |
| Product-type completeness | /10 | Does it include the required roles, screens, states, slides, or preview assets for its product type? |
| Buyer usability | /10 | Can the target buyer clearly understand, edit, reuse, and trust the template? |

## Critique Output

When reviewing a design, summarize:

1. Overall score.
2. Lowest scoring categories.
3. Specific visual issues.
4. Concrete revisions.
5. Concrete improvements applied, if editing code or design files.
6. Whether another revision pass is needed.
7. Whether medium fit and originality are strong enough for final delivery.

For any failed category, add:

- PASS/FAIL
- Failure category
- Evidence
- Root cause
- Required action
- Needed action type: rebuild, recompose, recolor, rewrite, or source repair
