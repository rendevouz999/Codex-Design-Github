# Website Template Design System Scope

## Foundations

- Color roles, typography scale, spacing scale, grid, radius, shadow, image treatment, icon style, and breakpoints.
- Section rhythm rules for dense, medium, and spacious blocks.
- Header and footer systems, including desktop and mobile navigation behavior.
- Explain color, type, spacing, radius, surface, and effect roles as functional decisions. Do not stop at visual swatches and samples.

## Components

- Buttons, links, nav items, dropdowns, forms, inputs, selects, checkboxes, cards, media frames, badges, accordions, tabs, modals, pagination, breadcrumbs, and alerts.
- Reusable section components: hero, proof band, feature grid, service card, process step, testimonial, pricing/package, FAQ, blog card, contact form, footer.
- Show component anatomy, variants, and states for the components that matter to the template. A single button sample is not sufficient.
- Include reusable section-module specimens or diagrams so buyers understand how to extend the template.

## Product-Specific Scope

- Ecommerce: product cards, category cards, cart rows, checkout forms, account panels, filters, wishlist, order states.
- Dashboard/admin: app shell, sidebar/topbar, KPI cards, charts, tables, filters, drawers, forms, empty/loading/error states.
- Portfolio/agency: project cards, case-study sections, image galleries, service packages, team/profile cards.
- Blog/editorial: post cards, author blocks, category filters, article body typography, newsletter module.

## Responsive Scope

- Desktop, tablet, and mobile behavior must be planned.
- Navigation collapse, image crop behavior, card wrapping, form stacking, table handling, and text overflow must be explicit.
- Do not create desktop/tablet/mobile responsive preview boards by default for single Figma website/template builds. Visible responsive preview boards are opt-in unless requested or required.
- If responsive preview boards are omitted, include a compact responsive behavior note in the design system instead.

## Compact But Complete Rule

A design system may be concise, but it must not be minimalist in coverage. Minimum standard:

- Foundations with functional roles.
- Component anatomy.
- Variants and states.
- Reusable section modules.
- Placeholder replacement rules.
- Surface/effect tokens.
- Source-editing guidance.

If the board only contains swatches, typography, a button sample, and generic notes, fail it as a token receipt rather than a design system.
