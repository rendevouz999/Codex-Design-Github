# Codex Design Brain: presentation design templates

Codex-Design focuses on reusable presentation templates and decks. One capability, `skills/presentation-deck`, owns shared design plus native PowerPoint/PPTX and HTML/browser output modes.

## Start here

Read AGENTS.md, `.design-brain/PRESENTATION_SCOPE.md`, the full PRESENTATION_TEMPLATE_GUIDE.md for template work, and `skills/presentation-deck/SKILL.md`. The selected native/web workflow owns concrete authoring and verification. Generic decks and explicit Keynote/Google Slides/Figma presentations remain valid host-directed context; verify target-specific tools and dimensions before production.

Retained support includes memory/offline recovery, references and Figma/source import, typography/color/layout, SVG/assets/icons/data visualization, style/craft, cognition/originality/simulation, sequential lifecycle, native/browser/render/visual QA, editable systems, host orchestration and deck packaging when the active delivery contract permits it.

The local design simulation uses an architectural idea only. It does not bundle, copy, import, or execute MiroFish source code. It does not run OASIS or social/public-opinion simulation. It adapts the architectural idea into a local design review and quality-gate workflow.

Standalone website/landing/dashboard/app/UI/brand/email/social/static/vector/editorial products have been separated recoverably. They are not active modules or SDK profiles. HTML/browser/SVG/PDF support remains because presentations need it. Historical evidence is preserved and does not reactivate retired routes.

## Entry points

- `python scripts/design_brain_module_select.py --task "create a PowerPoint template" --json --dry-run`
- `python scripts/design_brain_template_plan.py --template-type "PowerPoint presentation template" --dry-run`
- `python scripts/design_brain_template_orchestrate.py --template-type "HTML presentation template" --dry-run`
- Native: `python skills/presentation-deck/runtime/presentation.py` (read native workflow first)
- Web: `skills/presentation-deck/runtime/web/` plan/audit/render tools (read web workflow first)
- Source/routing boundary: `python scripts/test_design_brain_presentation_scope.py`

These examples are not evidence that tools/dependencies or external target transports are installed. Optional SDK execution requires its own explicit selection, authorization and authentication; source planning performs no paid calls. Shared memory availability is independent of checkout presence.

## Quality and delivery
